# AI-augmented Software Composition

This repository aims to be a collection of topics, practices and templates, leading into a model of how software could be composed in a modern, AI-augmented way using generative AI tooling. The content is CC-BY 4.0.

# Overview

The model augments the established software development lifecycle and delivery processes by use of GenAI coding agents, wherever applicable and appropriate. While most of the tools in the generative AI coding space focus on code generation, this content here does not solely focus on code or specific aspects of managing a codebase. It aims at covering a wider range of topics from requirements engineering, software architecture and design to software development. Therefore it is based on the learnings of [specification-driven development](https://speckit.org/) as well on the [Software Engineering Body of Knowledge (SWEBOKv4)](https://ieeecs-media.computer.org/media/education/swebok/swebok-v4.pdf)

It applies to Software Architecture, Design, Construction, Testing and Maintenance, in varying degrees of support, aiming to bridge the gap between what has become known as „Vibe Coding“ and professional software development beyond the MVP stage.

The following content describes a framework and collects practices of how to best give inputs to language models and generative AI coding agents.

# Objectives and Scope

If largest parts of code are generated by AI, the focus of human work shifts to controlling both input to AI (requirements of any kind) and the output from AI (regarding software verification and validation).

The primary objective is to have a proven and stable process for collaboration between humans and AI on software creation, with focus on professional, enterprise-grade software development practises.

In targeted scenarios, at least 90% of code and configuration in a software development project is produced by AI.
Therein, AI augments relevant parts of the Software Development Lifecycle (SDLC), leading to fundamental changes in the way we produce working software (regarding organization of teams, collaboration processes, estimations and more).

# Affected parts within the SDLC

Obviously, generative AI can assist in many aspects of the Software Development Lifecycle. This model covers only some knowledge areas, and aims to support up to a certain level.

| SDLC Knowledge Area | Level of augmentation | Example |
|---------------------|-----------------------|---------|
|Requirements Engineering|25%|AI should assist in making a set of requirements complete|
|Software Architecture | 50% | AI should assist on research of best practices, architecture patterns and producing requirements |
| Software Design | 50% | AI should assist of producing working sketches of software module designs |
| Software Construction | >=90% | The majority of code should come from a Generative AI source, derived from proper requirements |
| Software Testing | 25% | AI should assist in sketching out new unit test and integration test code, but not touch existing test surface |
| Software Maintenance | >=75% | AI should assist in defect fixing and refactoring, properly guarded by requirements |
